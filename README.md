# Forecasting LLM Token Load and Detecting Traffic Bursts

This repository provides a leakage-aware comparison of Persistence, 24-hour Seasonal Naive, XGBoost, and a single-layer LSTM on the public [BurstGPT v2.0](https://github.com/HPMLL/BurstGPT/releases/tag/v2.0) workload traces.
It forecasts total token demand 5, 15, and 60 minutes ahead and separately evaluates whether the forecasts detect high-load windows.

The main result is not a universal model ranking.
On the primary 15-minute test set, LSTM has the lowest MAE, but none of the four methods detects any of the five observed bursts at the fixed training-period P95 threshold.
On the zero-shot BurstGPT batch 3 test, Persistence is the strongest 15-minute method by both MAE and F1.
The results show that average forecast accuracy, threshold calibration, and temporal transfer must be evaluated separately.

## Research questions

1. Which historical workload and request-composition features are useful without exposing future information?
2. Do XGBoost or LSTM improve on simple operational baselines under a strict chronological split?
3. Can continuous load forecasts also identify capacity bursts under temporal distribution shift?

## Experimental design

| Item | Definition |
| --- | --- |
| Target | Sum of request and response tokens in each five-minute window |
| Window | Left-closed and right-open interval `[t, t + 5 min)` |
| Forecast origin | `t`, with the latest input from the completed window at `t - 5 min` |
| Horizons | 5, 15, and 60 minutes |
| Primary data | BurstGPT v2.0 `without_fails` batches 1 and 2 |
| Robustness data | Batch 3, used only as a zero-shot cross-period test |
| Split | Chronological 70% train, 15% validation, and 15% test by target time |
| Burst label | `token_load >= P95(training token_load)` |
| Model selection | Validation MAE only, with deterministic tie-breakers |
| Random seed | 42 |

All lags and rolling features are shifted by one complete window.
Scalers, thresholds, and fitted statistics use training data only.
Hyperparameters and stopping decisions use validation data only.
The test partition is reserved for post-freeze reporting.

The public timestamps are relative seconds from an undisclosed origin.
The pipeline maps them to a synthetic UTC index anchored at 1970 only for resampling, so the resulting dates must not be interpreted as real weekdays, weekends, or holidays.

## Results

The following values come from the latest unified evaluation artifacts generated by `src/07_evaluate.py`.
MAE and RMSE are measured in tokens per five-minute window.
Intervals are 95% synthetic-UTC calendar-day block-bootstrap confidence intervals with 1,000 replicates.

### Primary 15-minute test set

| Model | MAE | 95% CI | RMSE | sMAPE | MAE vs Seasonal Naive |
| --- | ---: | ---: | ---: | ---: | ---: |
| Persistence | 12,300 | 6,710-18,400 | 37,200 | 74.8% | +21.7% |
| Seasonal Naive | 15,800 | 8,020-24,300 | 41,900 | 91.4% | 0.0% |
| XGBoost | 16,500 | 9,170-24,500 | 34,700 | 130.0% | -4.4% |
| **LSTM** | **11,100** | **5,700-17,300** | **30,900** | **88.1%** | **+29.9%** |

The test set contains 5,228 target windows.
LSTM has the lowest MAE and RMSE, while Persistence has the lowest sMAPE.
The confidence intervals overlap substantially, so the point estimates should not be read as proof of a stable universal ranking.

### Fixed-threshold burst detection

The training-only P95 threshold is 315,246.2 tokens per five-minute window.
Only five primary test windows exceed it, compared with 1,220 training windows, which exposes a strong distribution shift.

| Model | Precision | Recall | F1 | Average precision | TP / FP / FN / TN |
| --- | ---: | ---: | ---: | ---: | ---: |
| Persistence | 0.000 | 0.000 | 0.000 | 0.00537 | 0 / 5 / 5 / 5,218 |
| Seasonal Naive | 0.000 | 0.000 | 0.000 | 0.00684 | 0 / 4 / 5 / 5,219 |
| XGBoost | 0.000 | 0.000 | 0.000 | 0.0113 | 0 / 2 / 5 / 5,221 |
| LSTM | 0.000 | 0.000 | 0.000 | 0.0108 | 0 / 0 / 5 / 5,223 |

No model detects a true burst at the fixed threshold.
Average precision is ranking evidence, not a substitute for fixed-threshold operational performance.

### Zero-shot cross-period robustness

Batch 3 is never used to fit a model, scaler, threshold, or hyperparameter.
At the 15-minute horizon, Persistence records MAE 43,800 and F1 0.711, compared with LSTM at MAE 53,500 and F1 0.520 and XGBoost at MAE 61,800 and F1 0.509.
This reversal reinforces the importance of strong baselines and explicit cross-period validation.

The workflow has been run with PowerShell, 16 GB RAM, and no GPU.
TensorFlow can run on CPU, but LSTM training is the slowest stage.

## Reproduce the experiment

Restore `configs/base.yaml` as described in the warning above before running these commands.
Run every command from the repository root and stop if a stage fails.

### 1. Clean and aggregate the traces

```powershell
python src/01_clean.py
python scripts/validate_week1_outputs.py
python src/02_build_series.py
python scripts/build_eda_notebook.py
python scripts/validate_week2_outputs.py
```

This stage reports every removed-row category, builds a complete five-minute grid, preserves zero-request windows, defines chronological splits, and freezes the training-only P95 threshold.

### 2. Build leakage-safe features and baselines

```powershell
python src/03_features.py --horizons-minutes 5 15 60
python src/04_baselines.py --horizons-minutes 5 15 60
```

### 3. Train and freeze XGBoost

```powershell
python src/05_xgboost.py --horizons-minutes 5 15 60 --n-iter 12 --shap-sample-size 2000
python scripts/validate_week3_outputs.py
```

The search evaluates 12 predefined random candidates per horizon with seed 42 and selects by validation MAE.

### 4. Train and freeze LSTM

```powershell
python src/06_lstm.py --horizon 5 --horizon 15 --horizon 60 --max-runs 1
python scripts/validate_week4_outputs.py
```

The default formal budget evaluates one bounded architecture per horizon.
Use repeated `--horizon` options because the script does not accept `--horizons-minutes`.

### 5. Run unified evaluation

```powershell
python src/07_evaluate.py --bootstrap-replicates 1000
python scripts/validate_temporal_contract.py
python scripts/validate_week5_outputs.py
```

This stage aligns all four methods on the same targets, computes regression and burst metrics, creates confidence intervals, and produces the final figures.

### 6. Run optional robustness and ablation experiments

```powershell
python src/11_week5_experiments.py --force-clean --bootstrap-replicates 500
python src/12_visualize_w5_python.py
python scripts/validate_temporal_contract.py
python scripts/validate_week5_outputs.py
python scripts/validate_w5_visualizations.py
```

This stage performs the predefined XGBoost ablations and the batch 3 zero-shot evaluation using frozen primary models.

## Reproducibility and validation

- The global seed is 42 for Python, NumPy, XGBoost, and TensorFlow.
- Feature and target partitions are assigned by target time rather than feature time.
- Empty windows remain in the complete time grid.
- Predictions are checked for temporal alignment, duplicates, missing values, and consistent targets.
- XGBoost test files are not opened during hyperparameter selection.
- LSTM scalers use training data only, and validation controls early stopping and epoch selection.
- Final confidence intervals use complete synthetic-UTC calendar-day blocks.
- Validation scripts raise errors on missing or inconsistent artifacts.

The full `01`-`07` run previously took about 110 minutes on an 8-core CPU with 16 GB RAM and no GPU.
Runtime depends strongly on TensorFlow, the CPU backend, and storage speed.

## Troubleshooting

### `configs/base.yaml` is missing

```powershell
git restore --source=777c38f -- configs/base.yaml
```

Review the restored configuration before running the pipeline.

### A raw input file is missing

Confirm that all four CSV files use the exact local names listed above.
The current cleaner does not treat batch 3 or the failure-audit file as optional.

### `series_5min.parquet` is missing

Run `src/01_clean.py` and then `src/02_build_series.py`.

### Feature partitions are missing

Run `src/03_features.py` before either model script.
The baseline stage does not create model features.

### TensorFlow fails to install or import

Use 64-bit Python 3.12 and install the pinned `requirements.txt` in a new virtual environment.
Do not mix packages from an existing global Python environment.

### Results differ from the table above

Check the raw file versions, pinned dependencies, YAML configurations, seed, CPU or GPU backend, and whether all stages were rebuilt in order.
Treat the generated CSV tables as canonical and report any incomplete validation explicitly.

## Limitations

- The public trace has no unique request identifier, so exact duplicate removal may also remove legitimate concurrent requests that share every public field.
- The synthetic UTC dates have no real calendar meaning.
- The primary test set contains only five burst windows, which makes threshold metrics and confidence intervals unstable.
- A fixed training-period P95 threshold is poorly calibrated after the observed load distribution shifts.
- The comparison covers one bounded XGBoost search and a small single-layer LSTM, not the full forecasting model space.
- Results apply to the released BurstGPT periods and are not production guarantees.
- Raw data and generated artifacts are not distributed in this repository.
- A fresh clone is not fully reproducible until `configs/base.yaml` is restored to the tracked project state.
