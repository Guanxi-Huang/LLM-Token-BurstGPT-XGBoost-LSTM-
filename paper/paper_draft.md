# LLM 服务 Token 负载预测与突发流量识别：基于 BurstGPT 真实轨迹的 XGBoost 与 LSTM 比较

## 摘要

生成式 AI 服务的容量压力同时取决于请求到达和输入、输出 Token 长度，因而仅预测请求数难以完整描述推理负载。本文使用 BurstGPT v2.0 请求轨迹，将 5,058,910 条清洗后主批次请求聚合为 34,848 个左闭右开的 5 分钟窗口，比较 Persistence、Seasonal Naive、XGBoost 与单层 LSTM 对未来 5、15、60 分钟总 Token 负载的预测，并用仅由训练集确定的固定 P95 容量阈值评价突发识别。为避免未来信息泄漏，所有切分按目标时间连续进行；在预测原点 `t`，模型最后可用的完整窗口为 `t-5min`，目标为 `t+h`；scaler、阈值和统计特征仅在训练范围拟合，超参数只由验证集选择。15 分钟主测试中，LSTM 的 MAE 为 11,054.5 Token/5min，优于 Persistence（12,342.4）、Seasonal Naive（15,770.3）和 XGBoost（16,464.4）。然而测试期只有 5 个固定阈值突发窗，四种模型的 F1 均为 0；XGBoost 的 AP 最高（0.0113），但只表明极弱的排序差异。批次 3 零样本迁移中 Persistence 的 15 分钟 MAE（43,838.2）和 F1（0.711）均最优，显示模型排名会随时期和突发基率变化。结果说明总体点预测、固定容量超限和跨时期迁移是三个不同问题，不能用单一指标替代。

**关键词：** LLM serving；Token 负载；时间序列预测；突发识别；XGBoost；LSTM；可复现研究

## 1 引言

### 1.1 研究问题

LLM 推理服务的资源消耗不仅由请求数决定，也受 prompt 和生成长度、模型类型及服务形态共同影响。真实工作负载具有长尾、周期与突发性 [1–3]；KV cache、批处理和 prefill/decode 调度进一步使 Token 规模与有效容量直接相关 [4–9]。因此，提前获得短期 Token 负载信号可能帮助容量和调度，但这种系统意义不等同于已经证明节能或 SLO 收益。

本文回答三个问题：RQ1，四类方法在未来 15 分钟总体 Token 负载误差上有何差异？RQ2，总体 MAE 更低是否同时意味着训练集 P95 固定阈值下的突发识别更好？RQ3，结论在 5/60 分钟、最小特征消融和 BurstGPT 第 3 批零样本迁移中是否保持？

### 1.2 贡献

第一，本文定义了可审计的时间契约：窗口时间戳为左边界，目标时间决定切分，预测输入完整结束于原点之前。第二，在同一目标时间、阈值和测试集合上比较两个强基线、XGBoost 和小型 LSTM，同时区分点预测、阈值决策和排序能力。第三，提供逐窗预测、配置、验证日志、双工具图册、文件哈希和从干净环境复跑的 README。贡献是公平协议与证据链，而非新的网络结构。

## 2 相关工作

### 2.1 工作负载与服务系统

Resource Central 和 Azure Functions 研究显示，大型云负载同时具有异质性、周期性与集中性 [2,3]。Orca、PagedAttention、AlpaServe、Splitwise、DistServe 和 DynamoLLM 分别从批处理、显存、并行、多阶段部署与动态资源控制说明了 Token 长度和突发到达的系统价值 [4–9]。这些研究支持本文的应用动机，但它们主要评价 serving 系统，不直接回答真实轨迹上的预测精度。

### 2.2 预测方法

Persistence 和季节朴素法为短期惯性和周期性提供必要参照；M4 结果也提醒复杂模型不应被预设为必然优于强基线 [12]。XGBoost 通过正则化树提升学习非线性特征交互 [10]，LSTM 则通过门控状态表达长序列依赖 [11]。两者的公平比较必须共享输入可用时刻、目标切分和验证规则。

### 2.3 研究缺口

BurstGPT 提供真实生成式 AI 请求的相对时间、输入/输出 Token、模型和日志类型 [1]，但现有工作较少在同一轨迹上同时区分总体回归误差、固定容量阈值超限和跨时期迁移，并完整公开防泄漏证据。本文以该缺口为边界，不把相关性结果外推为基础设施收益的因果证明。

## 3 数据与时间切分

### 3.1 请求级清洗与 5 分钟聚合

主实验使用 `without_fails` 第 1、2 批；第 3 批只作零样本稳健性，`complete_1` 只作失败请求审计。清洗依次检查时间可解析、Token 数值、关键字段缺失、非负约束和全字段精确重复。批次 1 从 1,404,294 行减至 1,363,384 行，批次 2 从 3,784,213 行减至 3,695,526 行；删除项全部是全字段重复。由于原始数据没有请求 ID，精确重复删除可能误删并发同值请求，这是保留的局限。

对请求 `i`，定义 `total_tokens_i = request_tokens_i + response_tokens_i`。令窗口宽度 `Δ=5min`，第 `k` 个窗口为 `[b_k,b_k+Δ)`，则请求数和 Token 负载为：

`N_k = Σ_i 1(b_k ≤ τ_i < b_k+Δ)`

`y_k = Σ_i 1(b_k ≤ τ_i < b_k+Δ) × total_tokens_i`。

聚合后补齐完整规则网格，零请求窗保留且 `N_k=y_k=0`。人工抽样窗口重新回到请求级 Parquet 复算 Token、请求数、均值和构成，均与聚合表一致。

### 3.2 目标时间 70/15/15 切分

公开时间为相对秒，因此转换为 UTC 仅用于单调索引，不能解释为真实日期、星期或节假日。完整序列按目标时间连续划分：训练 24,393 窗（70.0%）、验证 5,227 窗（15.0%）、测试 5,228 窗（15.0%）。特征暖启动使不同预测窗口的可训练样本略少，但验证和测试目标集合保持完全一致。任何样本都不随机打乱跨越边界。

### 3.3 突发阈值

固定容量突发定义为 `y ≥ q_0.95(y_train)`；训练 P95 为 315,246.2 Token/5min，并原样应用于验证、测试和批次 3。训练、验证、测试的阈值突发窗分别为 1,220、157、5；测试正例率只有 0.0956%，因此 F1 的方差和可解释性必须与总体 MAE 分开。

## 4 模型、阈值与指标

### 4.1 时间契约与预测窗口

时间戳表示窗口左边界 `[t,t+5min)`。对预测原点 `t`，最后可用的完整窗口标记为 `t-5min`，目标标记为 `t+h`，其中 `h∈{5,15,60}` 分钟。Persistence 直接复制 `y(t-5min)`；Seasonal Naive 使用目标时刻前 24 小时的完整窗口。XGBoost 的全部历史量先 `shift(1)`，LSTM 的序列末端同样是原点前 5 分钟。专用校验脚本逐行检查 input end、origin 和 target 的间隔。

### 4.2 XGBoost

XGBoost 使用 36 个仅由历史可得的特征：8 个 Token 滞后、多个滚动均值/标准差/最大值、请求和平均输入输出 Token 的滞后统计、历史 GPT-4/API 占比，以及仅基于相对秒数的日/周正余弦相位。每个窗口评估 12 个候选，选择指标只有验证集 MAE；最终参数冻结后在训练+验证范围重拟合，测试只预测一次。SHAP 只解释冻结模型，不参与选参。

### 4.3 LSTM

LSTM 输入为 144×5 分钟（12 小时）的 10 变量序列，包括 Token、请求量、平均输入/输出 Token、历史 GPT-4/API 占比和相对日/周相位。网络为单层 LSTM(32, dropout=0.1) 接 Dense(1)，共 5,537 个参数；损失为 MAE，batch size 64，不打乱序列。特征 scaler 只拟合训练序列实际使用的唯一输入行，目标 scaler 只拟合训练标签；最佳 epoch 由验证 MAE 决定，15 分钟为第 45 epoch。最终负预测裁剪为 0；XGBoost 未对称裁剪，这一差异在局限中披露。

### 4.4 指标与统计推断

对 `n` 个目标，`MAE=n⁻¹Σ|y_i-ŷ_i|`，`RMSE=√(n⁻¹Σ(y_i-ŷ_i)²)`，`sMAPE=100·n⁻¹Σ[2|y_i-ŷ_i|/(|y_i|+|ŷ_i|+ε)]`。突发指标为 `Precision=TP/(TP+FP)`、`Recall=TP/(TP+FN)` 和 `F1=2PR/(P+R)`；AP 使用按预测分数排序的非插值平均精度，不称作梯形 PR-AUC。95% 区间按合成 UTC 日进行整块 Bootstrap，主结果 1,000 次、批次 3 为 500 次，seed=42。

## 5 总体准确率

### 表 4、图 11、图 13：15 分钟主结果

**观察到什么。** LSTM 在主测试期的总体 MAE 最低，而 XGBoost 没有优于两个强基线。**量化证据。** LSTM MAE 为 11,054.5 Token/5min，较 Seasonal Naive 改善 29.9%；Persistence 为 12,342.4，XGBoost 为 16,464.4。**可能原因。** 12 小时序列可能更直接吸收局部形状和水平变化，而有限训练规模、手工滞后特征及测试期负载下移可能削弱树模型的相对优势。**不应过度推断。** 单一匿名轨迹和单一测试时期不能证明 LSTM 一般优于 XGBoost；XGBoost 的相对劣势也不应表述为训练失败。

代表周曲线显示所有模型能跟随普通负载的大致方向，但尖峰幅度和局部相位仍有明显差异。该图按完整测试周总负载最接近中位数的客观规则选择，不是为了突出某个模型。

## 6 突发识别

### 表 5、图 12、图 14、图 15：固定训练 P95

**观察到什么。** 四种方法在主测试固定阈值下都没有命中真实突发，总体 MAE 最优与突发识别最优不一致。**量化证据。** 测试仅 5 个正例，四模型 F1 均为 0；XGBoost AP 为 0.0113、LSTM 为 0.0108，且 XGBoost 仍有 2 个假阳性。**可能原因。** 训练到测试的绝对负载明显下移，使 315,246.2 Token/5min 落在测试极端尾部；极少正例也使 PR 曲线离散。**不应过度推断。** 零 F1 不意味着模型毫无排序信息，但如此低的 AP 也不足以支持可部署的固定阈值检测。

最大真实负载附近的局部图显示，预测曲线均没有在正确时刻越过训练 P95。混淆矩阵将 TP/FP/FN/TN 全部显式报告，避免准确率被大量真负例主导。

## 7 误差、消融与稳健性

### 表 6、图 16–18：分组误差

**观察到什么。** 突发窗误差远高于普通窗，并随相对日/周相位和服务构成变化。**量化证据。** 表 6 同时报告各组样本数、MAE、RMSE 和 sMAPE；非突发 MAE 最低的是 LSTM，真实突发窗 MAE 最低的是 XGBoost。**可能原因。** 长尾目标、服务构成变化和负载水平漂移共同改变局部误差。**不应过度推断。** 目标时刻 GPT-4/API 占比只用于事后分组，不能作为在线可用的未来特征，也不能支持因果解释。

### 表 6a：XGBoost 最小消融

**观察到什么。** 完整 36 特征在验证集排名第一，但缩减特征组在测试期反而有更低 MAE。**量化证据。** 验证 MAE 依次为 23,925、25,020、26,458；测试 MAE 却为 16,464、15,264、13,881。**可能原因。** 历史服务构成与目标负载之间的关系跨时期变化。**不应过度推断。** 测试排名不能回写为新的特征选择；主模型仍是验证集选定的完整特征组，消融只作有限诊断。

### 表 7：BurstGPT 第 3 批零样本迁移

**观察到什么。** 跨时期模型排名发生变化，Persistence 同时取得最低 MAE 和最高固定阈值 F1。**量化证据。** 15 分钟 MAE/F1 为 Persistence 43,838.2/0.711、LSTM 53,509.2/0.520、XGBoost 61,795.3/0.509、Seasonal Naive 120,193.3/0.0377。**可能原因。** 第 3 批的负载水平、突发基率和构成不同，局部惯性比冻结模型的训练期关系更稳定。**不应过度推断。** 这是不使用批次 3 拟合、scaler 或选择的外部零样本检验，不等于批次 3 内重训后的可达到性能。

## 8 局限与意义

第一，真实年份和星期语义不可得，相对日/周相位不能解释为真实工作日或节假日。第二，主测试只有 5 个固定阈值正例，突发指标高度不稳定。第三，无请求 ID 时的精确重复删除可能误删并发同值请求。第四，LSTM 对负预测裁剪而 XGBoost 不裁剪，处理不完全对称。第五，只比较一个树模型和一个小型序列网络，未穷尽概率预测、在线更新和自适应阈值。

尽管如此，研究给出一个可审计结论：面向容量规划时必须明确区分平均误差、绝对容量超限和分布漂移。低 MAE 可以帮助普通时段的资源信号，但不能自动转化为突发告警能力；外部批次中强基线的回归，说明部署前应进行滚动回测和基线守护。

## 9 结论

在严格无泄漏协议下，LSTM 是 BurstGPT 主测试 15 分钟总体 MAE 最优模型，但四种方法对 5 个固定 P95 突发窗均未命中，XGBoost 仅在 AP 排序上略高。批次 3 零样本结果又由 Persistence 主导，证明总体预测、固定容量突发和跨时期稳健性是不同评价维度。本文不据测试集重选模型或阈值；最终价值在于公开这些边界以及可按 README 重建的证据链。
